# KnitNote 1.4.1 Nordic and Korean Localization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the proven KnitNote 1.4.0 localization system with Norwegian Bokmål, Swedish, Finnish, Danish, and Korean without redesigning language selection or changing user data.

**Architecture:** Reuse the centralized language list, shared picker, catalog contract harness, Watch snapshot locale field, terminology table, metadata validator, and release audit delivered by 1.4.0. Add five language cases and complete translations, then run the same cross-platform acceptance matrix for eleven total languages.

**Tech Stack:** Swift 6, SwiftUI, Foundation `Locale`, String Catalog (`.xcstrings`), Swift Testing, WatchConnectivity, Python 3 metadata validation, Xcode 26.

## Global Constraints

- 1.4.1 adds exactly Norwegian Bokmål `nb`, Swedish `sv`, Finnish `fi`, Danish `da`, and Korean `ko`.
- The full supported set becomes `en`, `zh-Hant`, `zh-Hans`, `de`, `fr`, `ja`, `nb`, `sv`, `fi`, `da`, and `ko`.
- Norwegian uses Bokmål (`nb`), not the ambiguous legacy `no` code and not Nynorsk (`nn`).
- 1.4.0 language behavior, fallback rules, user-data boundaries, Watch synchronization, and App Store truthfulness remain unchanged.
- No Icelandic, runtime machine translation, downloadable language pack, remote translation service, or data-format change.
- Every task uses TDD and ends in a focused commit.
- Implementation starts only after the released 1.4.0 source and exact release commit are available as the baseline.
