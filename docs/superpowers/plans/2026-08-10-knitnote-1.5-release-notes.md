# KnitNote 1.5.0 Release Notes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the stale 1.4.1 App Store release notes with truthful, consistent KnitNote 1.5.0 copy across all thirteen metadata locales.

**Architecture:** Keep repository metadata as the source of truth. Extend the existing per-locale `LANGUAGE_CONTRACTS` with a 1.5.0 release identity and reviewed representative tokens for the six approved concepts, then update only each package's `What's New` field. The production checker and tests reject stale versions, missing concepts, field-limit violations, and prohibited claims before any release-candidate work begins.

**Tech Stack:** Python 3 standard library, `unittest`, Markdown metadata packages, Swift package release-audit contracts.

## Global Constraints

- Preserve version `1.5.0`, build `9`, bundle identifiers, signing, runtime catalogs, source behavior, screenshots, and all non-`What's New` metadata fields.
- Every locale must describe counter reminders, direct value entry, improved iPad counter layout, Apple Watch coordination, Dutch support, and the Projects title following the selected app language.
- Do not claim background notifications, cloud sync, automatic pattern translation, deleted-project recovery, subscription, trial, price, purchase, publication, native acceptance, or physical acceptance.
- Do not archive, sign/export, upload, select an App Store Connect build, submit, merge, or push.
- Write tests first and observe the expected failure before changing the checker or metadata packages.
