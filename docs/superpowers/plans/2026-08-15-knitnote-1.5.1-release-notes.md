# KnitNote 1.5.1 Release Notes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace KnitNote's thirteen App Store `What's New` values with truthful, natural 1.5.1 copy, verify the repository-owned metadata, then prepare matching iOS and macOS App Store Connect version pages without submitting them.

**Architecture:** The repository remains the source of truth: `metadata_check.py` owns an immutable thirteen-locale copy map, relationship requirements, and prohibited-claim checks, while each locale Markdown file contains the exact approved value used on both platforms. App Store Connect work consumes only the reviewed repository values and records platform/build/configuration evidence before stopping at the final submission boundary.

**Tech Stack:** Python 3 `unittest`, Markdown metadata packages, Bash release audit, Git, App Store Connect web UI, existing signed KnitNote 1.5.1 (11) builds.

## Global Constraints

- Work only in the isolated `release/knitnote-1.5.1-metadata` worktree; do not modify the user's unrelated checkout changes.
- The release identity is exactly KnitNote `1.5.1` with iOS and macOS Build `11` already processed in App Store Connect.
- Supported metadata packages are exactly `da-DK`, `de-DE`, `el-GR`, `en-US`, `fi-FI`, `fr-FR`, `ja-JP`, `ko-KR`, `nb-NO`, `nl-NL`, `sv-SE`, `zh-Hans`, and `zh-Hant`.
- Change only each package's `What's New` field. Preserve Name, Subtitle, Promotional text, Keywords, Description, Support URL, Marketing URL, Privacy URL, screenshots, privacy answers, pricing, availability, and user-created content.
- Every locale must preserve three claims: custom folders for patterns; the Yarn Library title immediately follows the selected in-app language; and KnitNote offers an in-app route to the App Store when a newer public version is available.
- Do not claim push/background notifications, automatic or forced updates, automatic downloads, cloud/account delivery, automatic pattern classification, nested folders, cross-folder membership, user-content translation, subscription, price, publication, approval, native review, or physical-device acceptance.
- Use the same reviewed localized note on the iOS and macOS 1.5.1 version pages.
- Metadata-only changes do not require a new binary build, archive, export, or upload.
- Stop before either platform's final `Submit for Review` action. Submission, release, publication, push, tag, and destructive browser actions require separate explicit authorization.
