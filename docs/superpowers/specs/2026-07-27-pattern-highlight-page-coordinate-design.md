# PDF 織圖高亮頁面座標修正設計

## 問題

iPad 直向使用自動縮放，橫向改為符合頁面寬度。目前橫向與縱向高亮的位置以整個閱讀畫布的寬高比例計算，因此裝置旋轉後，PDF 頁面的尺寸與留白改變，同一個保存比例會落到不同的 PDF 文字位置。

## 目標

- PDF 織圖旋轉、重新排版或縮放後，高亮仍指向同一個 PDF 內容位置。
- 保留既有 `PatternReadingState`、各頁高亮資料與 archive 格式，不進行資料遷移。
- 保留現有高亮外觀、44 pt 拖曳範圍、VoiceOver 調整、頁面切換、筆記、手寫標記與計數器行為。
- 不改變圖片織圖目前的畫布座標行為。

## 採用方案

以目前 PDF 頁面在 `PDFView` 中的顯示範圍作為高亮座標基準。

`PDFReaderView` 取得目前頁面的 PDFKit 顯示範圍，並把範圍回傳給 `PatternReaderView`。`HighlightOverlay` 仍保存 0 到 1 的正規化位置，但 PDF 模式會在該頁面範圍內繪製和拖曳，而不是使用整個閱讀畫布。

既有保存值的意義維持為頁面內的位置比例，因此資料格式與欄位不變。

## 元件與資料流

1. `PDFReaderView.Coordinator`
   - 在初次載入、頁面切換、縮放及版面尺寸改變後取得目前頁面的顯示範圍。
   - 使用 PDFKit 的頁面座標轉換，回傳 `PDFView` 本地座標中的 `CGRect`。
   - 沒有可用頁面或範圍無效時回傳 `nil`。

2. `PatternReaderView`
   - 保存目前 PDF 頁面顯示範圍。
   - PDF 模式把此範圍交給高亮層；圖片模式維持現有全畫布行為。
   - 重新載入閱讀器時清除舊範圍，避免短暫套用到另一份織圖。

3. `HighlightOverlay`
   - 有有效 PDF 頁面範圍時，以範圍的 `minX`、`minY`、寬度與高度換算顯示位置及拖曳位置。
   - 沒有有效範圍時暫時使用整個可用畫布，避免載入期間高亮消失或無法操作。
   - 正規化值仍限制在 0 到 1。

## 版面與手勢

- 橫向高亮的寬度限制在 PDF 頁面範圍，垂直位置依頁面高度換算。
- 縱向高亮的高度限制在 PDF 頁面範圍，水平位置依頁面寬度換算。
- 拖曳座標扣除頁面範圍的起點後再正規化。
- 可見線條粗細、顏色及最小觸控範圍維持不變。

## 錯誤與相容性

- PDF 尚未完成排版、頁面不存在或換算結果不是有限且為正的範圍時，不保存無效座標。
- 旋轉只改變顯示範圍，不改寫保存的高亮比例。
- 不新增 archive 欄位，不提升 archive 版本。
- 完成作品的唯讀限制保持不變。

## 測試與驗收

自動測試：

- 頁面範圍改變時，同一個正規化值仍代表頁面內相同的相對位置。
- 從畫面拖曳位置反算正規化值時，會扣除頁面範圍的起點並限制在 0 到 1。
- 無效或缺少頁面範圍時安全退回全畫布。
- 現有高亮外觀與 VoiceOver 合約仍通過。
- 完整 Swift 測試、iOS 與 macOS 建置通過。

iPad 實機驗收：

1. 直向把橫向高亮放在容易辨識的一行。
2. 轉成橫向後仍圈住同一行。
3. 再轉回直向後仍圈住同一行。
4. 檢查橫向、縱向與十字模式。
5. 切換頁面、關閉並重新開啟後，各頁高亮位置仍正確。

## 不在本次範圍

- 更改高亮顏色、粗細或透明度。
- 改變圖片織圖的高亮座標系統。
- 把高亮寫入或輸出到原始 PDF。
- 重寫為 PDFKit 原生頁面覆蓋層。
