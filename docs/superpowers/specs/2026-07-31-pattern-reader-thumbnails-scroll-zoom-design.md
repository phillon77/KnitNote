# KnitNote 織圖縮圖、高亮跟隨與縮放持久化設計

日期：2026-07-31  
狀態：設計已口頭確認，待使用者審閱書面規格

## 目標

改善 iPad 橫向閱讀多頁 PDF 織圖的選頁、高亮定位與縮放一致性：

1. PDF 上方顯示可橫向滑動的頁面縮圖，點選即可跳頁。
2. iPad 橫向上下捲動或縮放 PDF 時，橫向與直向高亮都緊跟同一份頁面內容。
3. 使用者調整的 PDF 寬度在同一份織圖所有頁面共用，離開後重開仍保留。

本設計保留現有每頁獨立的高亮、筆記與手寫資料，不重寫 PDF 閱讀器，不變更織圖檔案與作品的連結關係。

## 已確認產品決策

- 縮圖列採固定精簡式，不另加收合按鈕或全頁縮圖總覽。
- iPhone、iPad 與 Mac 的多頁 PDF 閱讀器都顯示縮圖列，但依各平台可用寬度調整間距與縮圖寬度。
- 縮圖列只在多頁 PDF 顯示；單頁 PDF 與圖片織圖不顯示。
- 同一份織圖的縮放寬度在所有頁面共用，不為每頁保存不同寬度。
- 縮放寬度在按「好」離開後持久保存，重開同一份織圖時還原。
- 高亮位置繼續以頁面內容的標準化座標保存，不以螢幕位置保存。
- 實作順序是先修復高亮跟隨與縮放持久化，實機通過後再加入縮圖列。

## 現況與根因證據

### 高亮沒有跟著上下捲動

`PDFReaderView` 只在頁面或縮放通知時發布 `pageFrame`。現有 0.25 秒取樣只同步頁碼，不重新發布頁面框。因此使用者在放大的 PDF 內上下捲動時，PDF 頁面已移動，SwiftUI 高亮圖層卻仍使用舊的頁面框。

### 換頁後寬度還原

iPad 橫向使用 `fitWidth` 模式。每次 `PDFViewPageChanged` 都清除縮放簽章並重新套用 `fitWidth`，直接把 `scaleFactor` 設回最適寬度。同時，頁面同步邏輯會把閱讀狀態的 `zoomScale` 重設為 `1`，所以使用者調整的寬度沒有成為可還原狀態。

## 技術方案

採用事件驅動的 PDF 閱讀狀態橋接，不以高頻輪詢作為主要機制，也不把高亮改造成 PDF annotation。

### `PatternPDFViewportState`

新增單一狀態邊界，由 PDFKit adapter 發布：

- 目前頁碼
- 目前頁面在閱讀畫布中的 frame
- 目前縮放值
- 目前適合寬度基準值
- 是否正在使用者捲動或縮放

PDFKit adapter 在頁面變更、縮放變更、捲動位置變更與畫面旋轉時發布最新快照。不替換 PDFKit 內部 scroll view 原有的 delegate，避免破壞翻頁與手勢。只在數值真正變化時更新 SwiftUI 狀態。

### 高亮座標流程

1. 每頁橫向與直向高亮仍保存為 `0...1` 的頁面內容座標。
2. `PatternPDFViewportState.pageFrame` 將標準化座標投影到目前畫面。
3. PDF 捲動或縮放時只改變投影的 frame，不改寫高亮資料。
4. 使用者拖曳高亮時才將畫面座標反算回頁面座標，並在拖曳結束後保存。

這樣可以同時修正橫線與直線，不需要變更已保存的 `PatternPageState`。

### 共用縮放寬度

新增與 PDF 專用的「適合寬度倍率」狀態，不重用圖片閱讀器現有 `zoomScale` 語意：

`pdfWidthScaleRatio = currentScale / currentFitWidthScale`

- `1.0` 代表目前畫面的適合寬度。
- 使用者手動縮放結束後更新倍率。
- 換頁時依新頁面的適合寬度基準重算絕對 `scaleFactor`，不改寫倍率。
- 旋轉時依新畫布寬度重算，避免使用舊像素尺寸。
- 按「好」、App 進入非 active 或閱讀器正常離開時，與頁碼一起保存。
- 舊資料沒有此欄位時使用 `1.0`，不修改原有高亮、筆記、手寫或圖片縮放資料。
- 套用前依 PDFKit 當下允許的最小／最大縮放範圍限制，損壞或非有限值安全回到 `1.0`。

這個倍率屬於一份織圖在當前使用情境的閱讀狀態，不放入每頁 `pageStates`，因此該情境內所有頁面共用。同一織圖連結到不同作品時，依現有 `PatternProjectUsage` 規則分別保存閱讀狀態，不把其中一個作品的寬度強制套用到另一個作品。

## 頁面縮圖列

### 佈局與互動

- 放在 PDF 畫布正上方，高度約 70–80 pt，不延伸到安全區或底部翻頁控制。
- 水平滑動，縮圖維持原頁面長寬比，下方顯示頁碼。
- 目前頁以莓紅色外框與「目前頁」輔助狀態標示，不只靠顏色。
- 點選縮圖時使用現有 `PDFPageNavigator`、頁面轉場與保存邏輯，不建立第二條換頁通道。
- 使用者滑動 PDF、上一頁／下一頁或點縮圖後，縮圖列都自動讓目前頁保持可見。
- 點選目前頁不重載、不重設縮放，也不觸發不必要的保存。

### 產生與容量

- 延遲產生畫面上可見頁及其前後頁的縮圖，不同步一次渲染整份 PDF。
- 渲染在背景執行；轉離織圖或頁面離開預載範圍時可取消工作。
- 沿用可丟棄縮圖快取的安全、清理與容量原則，但快取鍵必須包含織圖 asset 版本與頁碼。
- 縮圖不進入手動備份、不嵌入主 JSON、不影響 App 安裝容量；快取丟失時可重新產生。
- 單頁產生失敗時顯示頁碼佔位，不阻止閱讀與其他頁選擇。

## 資料一致性

- 點縮圖、PDFKit 滑頁與上一頁／下一頁全部進入同一個頁面轉場流程。
- 離開舊頁前先保存該頁高亮、筆記與手寫；保存失敗時留在舊頁並顯示現有儲存錯誤。
- 成功換頁後載入目標頁的獨立高亮、筆記與手寫，然後套用文件級共用縮放倍率。
- 非當前 reader generation、過時的縮圖結果、舊頁面 frame 與舊縮放事件都不得覆寫新狀態。
- 高亮拖曳中、縮放手勢中與程式正在套用還原值時，事件需區分使用者操作與程式操作，避免回饋迴圈。

## 錯誤與降級行為

- PDF 頁面縮圖失敗只影響該縮圖，不讓 PDF 載入失敗。
- 縮放倍率無效時回到適合寬度，保留頁碼、高亮、筆記與手寫。
- 如果無法取得有效頁面 frame，高亮暫時隱藏而不回到畫布中央；取得有效 frame 後再恢復。
- 快速連續點選不同縮圖時，只接受最後一個請求，不讓中間頁的非同步回呼覆寫目標頁。

## 輔助使用與多語系

- 新文字同時提供繁體中文與英文。
- 縮圖的 VoiceOver 標籤為「第 X 頁，共 Y 頁」；目前頁增加 selected trait。
- 縮圖點擊區至少 44 × 44 pt，不只使用縮圖可見邊界當作點擊區。
- 動態字級放大時保留頁碼可讀性，不壓縮 PDF 到無法閱讀。
- 鍵盤與 VoiceOver 選頁使用與觸控相同的頁面轉場通道。

## 驗收規格

### 自動化

- 水平與垂直捲動改變頁面 frame 時，同一標準化高亮投影到新畫面位置。
- 縮放與旋轉後橫向、直向、十字三種高亮都不改寫頁面座標。
- 手動縮放倍率在頁 1 設定後，頁 2、頁 3 使用相同適寬倍率；重開後仍相同。
- 旋轉使用新畫布基準重算絕對縮放，不使用舊像素值。
- 縮圖延遲產生、取消、緩存鍵、頁面更新與失敗佔位有獨立測試。
- 縮圖點選、PDF 滑頁與底部翻頁都測試頁面轉場失敗回滾。
- 舊閱讀資料解碼後使用預設適寬倍率，現有每頁高亮、筆記與手寫不變。

### iPad 實機

使用同一個候選 Build 執行：

1. 直向開啟多頁 PDF，移動橫線與直線，記錄內容位置。
2. 轉橫向，放大後上下捲動到頁面頂部、中間、底部，確認兩條高亮持續貼合原內容。
3. 調整成明顯不同的寬度，依序使用底部下一頁、PDF 滑頁與縮圖點選，確認三種換頁都保留寬度。
4. 在不同頁設定不同高亮、筆記與手寫，快速連續點縮圖，確認無資料串頁。
5. 橫向→直向→橫向反覆兩次，確認頁碼、共用寬度、高亮內容位置不變。
6. 按「好」離開並重開，確認頁碼、寬度、每頁高亮、筆記與手寫還原。
7. 開啟 VoiceOver，驗證縮圖列順序、目前頁狀態與點選跳頁。

### 回歸驗收

- iPhone 多頁 PDF 顯示精簡縮圖列，直向與橫向不當機，不出現 AttributeGraph 迴圈。
- iPad 直向 PDF 不被底部翻頁控制遮擋。
- Mac 多頁 PDF 顯示縮圖列，鍵盤選頁正常；圖片織圖的閱讀、高亮、筆記與手寫現有行為不變。
- 分享匯入、織圖檔案匣、多作品連結與備份還原不受影響。

## 實作順序與版本邊界

1. 為捲動頁面 frame 同步建立紅燈測試，修正高亮跟隨。
2. 為換頁縮放重設建立紅燈測試，建立文件級適寬倍率並持久化。
3. 完成 iPad 橫向實機驗收；任一 bug 未通過時不加入縮圖列。
4. 建立延遲縮圖供應器與固定縮圖列，所有選頁入口使用同一轉場流程。
5. 執行完整自動測試、iOS/macOS Build 與 iPhone/iPad 實機回歸。

本工作納入 KnitNote 1.3 規劃，但不授權修改版本／Build、合併、推送、上傳或送審。實作完成後仍必須使用唯一候選 commit 完成實機驗收。

## 不在本次範圍

- 可收合縮圖列
- 全螢幕縮圖總覽
- 縮圖排序或拖曳重排 PDF 頁面
- 每頁獨立 PDF 縮放寬度
- 改寫或合併現有每頁高亮、筆記與手寫資料
- 將縮圖加入備份或主資料檔
- 與本閱讀器工作無關的大型重構
