# KnitNote 1.3 — Mac 新增作品單欄版面設計

## 目標

修正 Mac「新增作品」視窗被 `Form` 分欄、裁切與留白破壞的問題。畫面在預設、最窄與放大尺寸都必須維持單欄、清楚且可操作；iPhone 與 iPad 現有版面不變。

## 採用方案

Mac 不再使用 `Form`。`CreateProjectView` 保留共用資料與建立流程，但把內容分成平台專屬呈現：

- macOS：`ScrollView` 包住單欄 `VStack`，內容寬度置中並設合理上限。
- iOS/iPadOS：保留目前的 `Form`、相機與照片列。
- sheet 繼續使用 `.presentationSizing(.fitted)`，維持 520 點最小、620 點理想寬度與可放大能力。

## Mac 畫面順序

1. 「作品名稱」標籤與完整寬度文字欄位。
2. 「作品照片（選填）」標籤。
3. 190 點高的照片預覽，保持比例裁切與圓角。
4. 照片操作：預設寬度左右排列；最窄寬度上下排列，順序固定為「選擇／更換照片」後「移除照片」。
5. 「取消」與「建立」維持系統 sheet 工具列位置，不另做重複按鈕。

## 行為與狀態

- 不改建立作品、照片載入、錯誤訊息、試用限制或資料儲存流程。
- 空白名稱仍不可建立；照片載入中仍不可建立。
- 視窗縮窄時內容可垂直捲動，不得水平裁切。
- 所有文字沿用既有 localization key，不新增硬編碼語系文字。

## 無障礙與鍵盤

- VoiceOver 順序依視覺順序：名稱、照片標題、照片、選擇／更換、移除、取消、建立。
- Tab 順序不得因水平／垂直切換而改變。
- Escape 關閉；Return 不得繞過空白名稱或照片載入中的 disabled 狀態。

## 驗收

- Mac：620 點預設、520 點最窄、960 點放大三種尺寸均無分欄錯位、裁切或異常大片留白。
- 有照片時，620 點按鈕左右排列，520 點上下排列。
- Traditional Chinese 與 English 皆通過。
- 聚焦版面測試先紅後綠；macOS smoke test、iOS Simulator build 通過。
- 最終人工檢查使用非私密測試圖片，且不儲存測試作品。
