# KnitNote Mac 毛線編輯器單欄版面設計

日期：2026-08-03
狀態：使用者已核准設計

## 問題

Mac 版「新增毛線」與「編輯毛線」使用原生 `Form`。標準輸入欄位會被 macOS 排成兩欄，但建議棒針、建議鉤針等自訂範圍欄位會橫跨整個表單，造成標籤與輸入框左右錯位。單純增加 sheet 寬度或限制 `Form` 寬度只能改變留白，無法讓兩種欄位使用一致的對齊規則。

這是 Mac 專用的可見版面問題。iPhone 與 iPad 現有新增、編輯、掃描、照片及資料保存流程已通過驗收，不應因本次修正改變。

## 決策

Mac 版改用置中的單欄捲動編輯器，不再使用原生 `Form` 自動兩欄排版。每個欄位的標籤放在輸入元件上方，讓一般文字欄位、數值欄位與尺寸範圍欄位遵循相同的水平起點。

新增與編輯畫面共用同一套 Mac 欄位元件與分組順序：

1. 基本資料：品牌、系列、顏色與色號。
2. 標籤資料：染缸號、重量、長度、材質。
3. 建議尺寸：棒針與鉤針的最小值、最大值及單位。
4. 庫存資料：球數、剩餘數量等既有欄位。
5. 使用作品：維持現有的多作品連結能力。
6. 照片：維持展示照片與最多兩張標籤照片的既有操作。

掃描入口與掃描後的確認流程保持不變；本次只修正最終新增／編輯畫面的 Mac 版面。

## 架構

- `CreateYarnView` 與 `EditYarnView` 在 macOS 分支使用共用的 Mac 單欄編輯內容。
- 共用內容採 `ScrollView` 包住 `VStack(alignment: .leading)`，最大內容寬度為 560 pt，外層在 sheet 中水平置中並保留 28 pt 安全間距。
- 每個分組由清楚的標題及相關欄位組成；單一欄位由上方標籤與下方控制項構成。
- 尺寸範圍欄位在自己的分組內緊鄰排列，不使用跨整張 sheet 的 `Spacer`。
- iOS/iPadOS 繼續使用現有 `Form` 與現有欄位元件，不共用 Mac 專用版面容器。
- sheet 維持最小寬度 520 pt、理想寬度 620 pt、最小高度 560 pt，內容超出可用高度時以捲動顯示。

這個邊界讓欄位資料綁定與保存邏輯保持共用，只將平台版面分開。日後增加毛線欄位時，Mac 版需把新欄位放入明確分組；不再依賴 `Form` 自動推測欄位角色。

## 資料與操作

- 所有欄位仍直接綁定目前新增／編輯畫面的既有 view state；不新增資料模型或遷移。
- 「完成」沿用目前的驗證、保存、照片安裝與錯誤處理流程。
- 「取消」與 Escape 沿用目前行為，不保存草稿。
- 建立與編輯的照片選擇、標籤照片管理、掃描結果、作品連結及錯誤訊息保持原有語意。
- Return、Tab 焦點順序與 VoiceOver 閱讀順序須與畫面由上到下的順序一致。

## 視覺與本地化

- 延續白色圓角內容、水彩背景及莓紅色重點色，不新增新的視覺語言。
- 繁體中文與英文使用同一欄寬；長標籤可自然換行，不得截斷或與欄位重疊。
- 最小視窗寬度仍能看到完整欄位；較寬視窗只增加外側留白，不把表單重新拆成兩欄。
- 動態字級放大時欄位向下延伸，保持單欄與可捲動。

## 錯誤處理

本次不改變業務錯誤模型。保存失敗時保留輸入內容並顯示既有錯誤；掃描、照片或作品連結錯誤沿用現有可重試流程。版面不得因錯誤訊息出現而裁切主要操作。

## 驗收

### 自動驗證

- 加入 Mac 版面契約測試，證明新增與編輯畫面使用單欄 `ScrollView`／`VStack`，而不是 Mac 原生 `Form`。
- 證明新增與編輯共用同一個 Mac 欄位內容，且 iOS/iPadOS 仍走原有 `Form`。
- 執行相關毛線測試、完整 Swift 測試，以及 iOS 與 macOS build。

### Mac 實機驗收

- 在預設及最小視窗尺寸分別開啟新增與編輯毛線。
- 確認所有標籤與欄位同一起點、無左右分裂、無截字與不合理空白。
- 建立一筆不含私人照片的臨時毛線，再開啟編輯畫面確認相同版面；驗收後刪除測試資料。
- 分別切換繁體中文與英文，測試長文字、捲動、Tab／Return／Escape、VoiceOver 與放大字級。
- 確認掃描入口、標籤照片、作品連結與保存結果仍可使用。

### 回歸保護

- iPhone 與 iPad 的新增、編輯、掃描及照片流程不得有版面或行為變更。
- 不修改毛線資料格式、備份內容、OCR、作品關係、StoreKit、版本或 Build。

## 不在本次範圍

- 不重新設計 iPhone 或 iPad 毛線表單。
- 不新增或刪除毛線欄位。
- 不改變 OCR 辨識、照片壓縮、備份或還原。
- 不調整作品詳情或毛線庫列表。
- 不進行推送、合併、上架、版本號或 Build 號變更。
