# KnitNote 1.5 Counter Reminders and Dutch Localization Design

**Date:** 2026-08-09

## Goal

KnitNote 1.5 makes project counters easier to manage on iPad, lets users enter a counter value directly, and adds an optional next-step reminder to each counter. It also adds complete Dutch localization and fixes the project page title that currently remains in Traditional Chinese under other app languages.

The work must preserve all existing projects, patterns, counters, notes, links, yarn data, and completion state.

## Scope

### Included

- A larger adaptive counter-management presentation on iPad.
- Direct entry of a non-negative counter value on iPhone, iPad, and Mac.
- One optional active reminder per counter.
- One-time and repeating row reminders.
- Reminder cards on iPhone, iPad, and Mac.
- Watch reminder haptics and acknowledgement.
- Complete Dutch localization across the shipping products and store metadata.
- Localization of the large project-page title in every supported language.
- Accessibility and physical-device acceptance for the changed flows.

### Excluded

- A separate reminder center.
- More than one active reminder per counter.
- Time- or calendar-based notifications.
- A postpone or snooze action.
- Translation of user-created or imported content.
- Rewinding reminder history when a counter decreases or resets.

## Chosen Product Approach

The reminder is embedded in the counter manager and stored with its counter. This keeps the action close to the row count it describes and lets the existing project and Watch synchronization paths carry the state.

Rejected alternatives:

- A separate reminder center adds navigation and management complexity for a feature whose meaning depends on one counter.
- System notifications are a poor fit because the trigger is a counter value, not a clock time.

## User Experience

### Counter manager

On iPad, the counter manager is a large centered adaptive presentation in both portrait and landscape. The name, current value, decrement, increment, reset, and reminder controls must be discoverable without scrolling. The content may adapt its spacing and columns, but the essential controls cannot fall below a clipped or initially hidden area.

On iPhone, the controls use a narrow single-column layout. On Mac, they appear in a resizable management presentation. All three platforms expose the same counter and reminder capabilities.

The large value has an edit affordance. Tapping the value enters edit mode. The editor:

- accepts decimal whole numbers from zero upward;
- rejects empty, negative, fractional, non-numeric, and overflowing values;
- provides explicit Save and Cancel actions;
- leaves the stored value unchanged when validation fails;
- respects the existing rule that counters in a completed project cannot be changed until the project is resumed.

The existing decrement, increment, and reset operations remain available. Reset retains its destructive confirmation.

### Reminder editor

Each counter can have zero or one active reminder. The reminder editor is part of the same counter-management presentation.

The user selects one of two modes:

1. **One-time:** remind at one target value greater than the counter value at the time the reminder is saved.
2. **Repeating:** remind every `N` rows, where `N` is a positive integer. The first target is the value at save time plus `N`.

A repeating reminder can have an optional positive repetition count. If the count is omitted, it continues indefinitely until stopped. A custom reminder message is optional. If it is empty, the localized default is “Reached row X,” using the actual due row.

Saving a replacement reminder replaces the existing reminder for that counter after confirmation when the prior reminder has progress or an outstanding occurrence.

### Trigger and acknowledgement

All counter changes use the same reminder evaluator: increment, decrement, reset, direct entry, and Watch commands.

A reminder becomes due only when the value moves upward across its target. Moving downward or resetting never rewinds completed progress and never makes an acknowledged target eligible again.

When direct entry crosses multiple repeating targets, KnitNote creates one combined pending reminder. The card reports how many occurrences were crossed instead of presenting multiple cards. The number of crossed occurrences is capped by the reminder’s remaining finite repetition count.

A pending card has exactly two actions:

- **Complete this reminder:** acknowledges all occurrences represented by the card and advances to the next target. A one-time reminder or a repeating reminder at its finite limit then becomes inactive.
- **Stop reminder:** deactivates the reminder and clears its pending occurrences.

If the card is not acted on, its pending state is persisted. Later upward changes can add newly crossed occurrences to the same pending card. Decrementing, resetting, leaving the reader, or restarting the app does not silently acknowledge or discard it.

The active iPhone, iPad, or Mac reader shows the card as soon as it observes a due reminder. If the relevant reader is not visible, the persisted card is shown the next time that project and counter are opened. Version 1.5 does not add background time notifications.

### Watch behavior

iPhone, iPad, and Mac can create and edit reminders. Watch can display a due reminder, play a haptic, complete it, or stop it; Watch does not edit reminder rules.

When a Watch counter action crosses a target, the Watch gives immediate local feedback from its synchronized snapshot and queues the counter mutation and acknowledgement through the existing Watch command path. Commands and acknowledgements carry stable identifiers so retries and reconnects are idempotent. A reconnect must not complete an occurrence twice or replay its haptic after the acknowledgement is merged.

If the Watch lacks enough synchronized reminder state to make a safe decision, it performs the counter command without inventing a reminder. The authoritative device response supplies any pending reminder after synchronization.

## Data Design

`ProjectCounter` gains one optional reminder value. Existing serialized counters decode a missing reminder as `nil`, so no destructive migration is required.

The reminder model contains at least:

- a stable reminder identifier;
- mode: one-time or repeating;
- anchor value captured when saved;
- target value for one-time mode or positive interval for repeating mode;
- optional finite repetition limit;
- acknowledged occurrence count;
- next target value;
- pending occurrence count and its covered target range;
- optional user message;
- active/stopped state;
- a revision or mutation timestamp needed by the existing merge strategy.

Reminder calculation belongs to a platform-neutral core component. UI views render its result but do not independently calculate due targets. Counter mutation returns a structured result containing the saved counter state and any newly due reminder summary.

Malformed reminder data is normalized fail-safe: preserve the counter and its value, disable the invalid reminder, and never delete or block the project. Invalid reminder data must not crash decoding or Watch synchronization.

## Synchronization and Conflict Rules

- Reminder state follows the existing project persistence and device synchronization boundaries.
- The counter and its reminder mutation are saved atomically from the user’s perspective.
- Duplicate Watch commands and duplicate acknowledgements are ignored by stable operation identifier.
- A newer explicit Stop action wins over an older queued acknowledgement.
- An acknowledgement can advance only the reminder identifier and pending occurrences it observed; it cannot acknowledge a newly replaced reminder.
- User-created names and reminder messages remain byte-for-byte user content and are never localized or rewritten.

## Localization

Dutch becomes a complete shipping language, bringing the runtime language set to thirteen. Coverage includes:

- the main iPhone, iPad, and Mac app;
- Watch app;
- Share Extension;
- InfoPlist permission and display strings;
- VoiceOver labels, values, hints, validation messages, and reminder text;
- help and onboarding text affected by this feature;
- App Store metadata prepared for the version.

The large project-page heading must use the same semantic localization source as the project navigation item. It must display correctly for every supported app language. The fix must not translate project titles entered by users.

Dutch copy requires the same key-domain completeness and release-audit protection as every existing language. Machine-shaped literal translations are not accepted as final linguistic evidence.

## Accessibility

- The editable value exposes its counter name, current value, and edit action.
- Save errors are announced and focus remains in the editor.
- Reminder controls announce mode, target or interval, repetition limit, next target, and active state.
- A combined reminder announces both the latest due row and the number of crossed occurrences.
- Complete and Stop have distinct labels, hints, and destructive semantics where appropriate.
- Dynamic Type cannot hide decrement, increment, reset, Save, or reminder-card actions.
- Keyboard navigation and focus order are verified on iPad hardware keyboard and Mac.

## Error Handling

- Invalid direct input never changes persisted data.
- Invalid targets, zero intervals, and non-positive finite repetition counts cannot be saved.
- Arithmetic is overflow-checked before calculating future targets. If a future target cannot be represented, the reminder stops safely after the last valid occurrence and reports a localized explanation.
- A persistence failure keeps the editor open with the prior stored state and an actionable localized error.
- A Watch transport failure leaves the operation queued and visibly pending; it does not falsely report authoritative completion.
- A malformed synchronized reminder is disabled without affecting the counter or project.

## Testing Strategy

### Core tests

- Backward-compatible decoding of projects without reminder fields.
- One-time and repeating target calculation.
- Finite and unlimited repetition behavior.
- Upward crossings from increment and direct entry.
- Combined occurrence calculation when several targets are crossed.
- Remaining-count capping for finite reminders.
- No rewind after decrement or reset.
- Pending-state persistence across reopen and process restart.
- Replacement, completion, and stop semantics.
- Invalid data normalization and arithmetic overflow safety.
- Completed-project mutation protection.

### Sync tests

- Reminder snapshot encoding and decoding.
- Offline Watch command and acknowledgement replay.
- Duplicate command and acknowledgement idempotency.
- Stop-versus-stale-acknowledgement conflict handling.
- Replacement reminder identifier protection.
- No duplicate haptic after a merged acknowledgement.

### UI and localization tests

- iPad portrait and landscape counter-manager geometry keeps all essential controls visible.
- iPhone and Mac layouts expose equivalent actions.
- Direct-entry validation, cancellation, save, and VoiceOver behavior.
- Reminder-card combined count and two-action contract.
- Project-page heading resolves through localization instead of a Chinese literal.
- Dutch and all existing catalogs have the required runtime, Watch, Share, InfoPlist, accessibility, and format/plural domains.
- User-created project, counter, and reminder text remains unchanged under language switching.

### Build and physical acceptance

- Full Swift test suite.
- iOS, macOS, Watch, and Share builds.
- Physical iPhone and iPad acceptance, including iPad portrait and landscape.
- Physical Watch reminder and reconnect acceptance.
- Mac visual, keyboard, and VoiceOver acceptance.
- Existing non-disposable projects and counter values are verified unchanged after installing over the prior version.

## Acceptance Criteria

The feature is accepted only when:

1. Essential iPad counter controls are visible without scrolling in portrait and landscape.
2. A user can safely enter and persist a non-negative integer value.
3. One-time and repeating reminders follow the approved crossing, completion, stop, and no-rewind rules.
4. Multiple crossed repeating targets produce one accurate combined card.
5. Watch haptic and acknowledgement work without duplicate completion across an offline reconnect.
6. The project-page heading is localized in every supported language.
7. Dutch is complete across all shipping products and approved metadata, while user content remains unchanged.
8. Automated tests and all four platform builds pass.
9. Required physical acceptance passes without loss or mutation of existing user data.

## Release Boundary

This design does not authorize changing the marketing version, archiving, signing, uploading, selecting an App Store build, editing live pricing or in-app purchases, submitting for review, merging, or pushing. Those remain separate explicit gates after implementation and exact-candidate physical acceptance.
