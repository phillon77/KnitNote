# KnitNote 織圖資料匣與毛線庫即時標題設計

日期：2026-08-13
狀態：使用者已核准設計，等待規格審閱

## 背景

下一版本先處理兩項使用者回饋：

1. 毛線庫的大標題有時停留在第一次開啟時的語言。即使使用者在 App 內切換語言，標題也不一定跟著更新。
2. 織圖庫目前只有單一清單。當收藏增加後，使用者希望能用自己建立的資料匣整理織圖。

既有織圖檔案匣設計刻意排除分類、自訂資料夾與標籤。本設計只在「單層、每份織圖恰屬一個位置」的明確邊界內新增資料匣，並取代該項舊限制；既有資產、作品連結、閱讀進度與刪除規則保持不變。

## 目標

- 毛線庫標題永遠依目前 App 內選擇的語言顯示，不要求重啟 App。
- 使用者可建立、重新命名及刪除單層織圖資料匣。
- 每份織圖最多屬於一個使用者資料匣；沒有資料匣時屬於系統「未分類」。
- iPad 與 Mac 使用資料匣側欄；iPhone 使用先選資料匣、再進入織圖清單的導覽流程。
- 現有織圖與所有相關使用者資料在升級、移動、刪除資料匣、備份及還原時完整保留。
- 所有新介面文字支援現有 13 種 App 語言，使用者建立的名稱維持原文。

## 非目標

- 不提供多層資料匣。
- 不提供標籤或讓一份織圖同時屬於多個資料匣。
- 不提供資料匣共享、雲端同步或協作。
- 不提供資料匣手動拖曳排序或批次移動織圖。
- 不重新設計織圖閱讀器、作品連結、原始檔所有權或永久刪除規則。
- 不翻譯、改寫或推測任何織圖名稱、備註、資料匣名稱或其他使用者內容。
- 不在本設計中決定版本號、Build、上架或 App Store metadata。

## 已核准的產品決策

- 一份織圖只能位於一個使用者資料匣。
- 資料匣只有一層。
- 刪除非空資料匣時，所屬織圖自動移至「未分類」。
- iPad／Mac 採左側資料匣、右側織圖的側欄版面。
- iPhone 先顯示資料匣清單，點入後才顯示該資料匣的織圖。
- 長按織圖後以「移到資料匣」變更歸屬。
- 側欄上方使用「＋」新增資料匣；長按使用者資料匣可重新命名或刪除。
- 在「全部」搜尋所有織圖；選定資料匣後只搜尋該資料匣。

## 毛線庫標題修正

### 根因邊界

`YarnLibraryView` 雖然讀取環境中的 `locale`，但目前以本地化 key 直接傳入 `navigationTitle`。大型導覽標題可能保留第一次解析的字串，而不隨 KnitNote 自訂 App 語言環境重新求值。

### 設計

- `YarnLibraryView` 明確使用目前環境 `locale`，透過 KnitNote 現有的 locale-aware resolver 解析 `yarn.library.title`，再把完成字串交給 `navigationTitle`。
- 使用者切換 App 語言後，返回或重新顯示毛線庫時，標題必須以新 locale 重新解析。
- 毛線卡片名稱、品牌、顏色及其他使用者輸入資料保持原文。
- iPhone、iPad 與 Mac 使用相同語意；不為單一平台保存獨立標題狀態。

## 資料模型

### PatternFolder

新增獨立的使用者資料匣模型：

- 穩定 UUID。
- 使用者輸入的顯示名稱。
- 建立時間，作為穩定次排序依據。

資料匣名稱是使用者內容，不進入 String Catalog，也不因 App 語言切換而翻譯。

### StoredPattern 歸屬

`StoredPattern` 新增可選的 `folderID`：

- `folderID` 指向存在的 `PatternFolder` 時，織圖屬於該資料匣。
- `folderID == nil` 時，織圖屬於系統「未分類」。
- 解碼、還原或修復時若 `folderID` 指向不存在的資料匣，正規化為 `nil`，不得因此丟棄織圖。

### 系統檢視

「全部」與「未分類」不是持久化的 `PatternFolder`：

- 「全部」是所有織圖的虛擬集合。
- 「未分類」是 `folderID == nil` 的虛擬集合。
- 兩者不能重新命名、刪除或被資料遷移覆蓋。
- 其顯示名稱由 String Catalog 依目前 App 語言取得。

這個設計避免把可本地化的系統名稱混入使用者資料，也避免使用者建立同名資料匣後破壞系統語意。新增或改名時應拒絕與現有 13 種 shipping locale 中任一「全部／未分類」譯名衝突，並以穩定的內部身分判斷系統項目；錯誤訊息只顯示目前 App 語言，不改寫使用者輸入。

## 名稱驗證

- 保存前移除名稱前後空白。
- 空字串不能保存。
- 同一層不允許經 locale-aware、大小寫不敏感比較後相同的名稱。
- 不允許名稱與任一現有 shipping locale 的系統「全部／未分類」顯示名稱相同。
- 驗證錯誤在編輯介面內顯示，保留使用者輸入並保持介面開啟。
- 本設計不以翻譯或自動修正變更使用者輸入的字詞。

## 儲存與交易語意

新增、改名、移動與刪除資料匣都必須透過 store 的單一交易完成：

- 新增資料匣：驗證名稱後一次保存模型。
- 重新命名：驗證目標資料匣及名稱後一次保存，不重寫每份織圖。
- 移動織圖：驗證織圖及目的資料匣仍存在後，只更新該織圖的 `folderID`。
- 刪除資料匣：同一交易先把所有參照該 ID 的織圖正規化為 `folderID == nil`，再移除資料匣。

任何驗證或持久化失敗時：

- 記憶體快照、選取狀態、資料 generation 與磁碟 archive 都不應發布部分變更。
- 編輯器或確認畫面保持開啟。
- 顯示目前 App 語言的可理解錯誤。
- 不自行重試造成重複資料匣或重複移動。

## 舊資料升級

- 舊 archive 沒有資料匣集合與 `folderID` 時，解碼為空資料匣集合，所有既有織圖的 `folderID` 為 `nil`。
- 升級不得改變 `PatternAsset`、`StoredPattern` ID、名稱、備註、作品 usage、頁碼、標記、縮圖或原始檔。
- archive schema 變更必須沿用現有可信任載入、原子安裝及回滾邊界。
- 損壞或重複的資料匣 ID、孤立參照及不合法名稱必須 fail closed 或安全正規化，不能造成整份織圖遺失。

## 備份與還原

備份新增包含：

- 所有使用者 `PatternFolder`。
- 每份 `StoredPattern` 的可選 `folderID`。

還原時必須先驗證資料匣 ID 唯一性與織圖參照，再原子安裝。孤立 `folderID` 正規化為「未分類」並保留織圖。備份不得把「全部」或「未分類」寫成可刪除的使用者資料匣。

## iPad 與 Mac 介面

採用已核准的側欄方案：

- 左側依序顯示「全部」、「未分類」及使用者資料匣。
- 每列顯示資料匣名稱及其中織圖數量。
- 右側維持現有織圖卡片／清單、搜尋、排序及新增操作。
- 選取側欄項目後，右側只顯示對應集合；「全部」顯示所有織圖。
- 側欄上方「＋」開啟新增資料匣介面。
- 長按或平台等價 context menu 提供重新命名與刪除。
- 使用者資料匣使用名稱排序，建立時間及 UUID 作為穩定次排序；不提供手動拖曳。
- 視窗縮窄時仍保留可操作的 sidebar/detail 結構，不把名稱截成無法辨識的單字元。

## iPhone 介面

- 織圖分頁的第一層顯示資料匣清單及織圖數量。
- 點「全部」、「未分類」或使用者資料匣，push 到既有織圖清單畫面。
- 子畫面標題顯示目前集合名稱，返回上一層可切換資料匣。
- 新增、改名與刪除入口和 iPad／Mac 使用相同語意。
- 不在窄畫面固定顯示兩欄，也不以橫向捲動模擬側欄。

## 新增與移動織圖

### 新匯入

- 從使用者資料匣或「未分類」內開始匯入，成功建立的織圖進入目前集合。
- 從「全部」開始匯入，成功建立的織圖進入「未分類」。
- Share Extension 或其他沒有明確目前資料匣的背景匯入進入「未分類」。
- 重複偵測若使用既有收藏，不因新的匯入入口擅自移動該既有收藏。

### 移動

- 長按織圖顯示「移到資料匣」。
- 目的地選單包含「未分類」與所有使用者資料匣，不包含「全部」。
- 目前位置可顯示勾選狀態；重選目前位置是無變更操作，不增加 generation 或重寫 archive。
- 移動後目前篩選不再包含該織圖時，織圖從畫面移除；不自動跳到目的資料匣。
- 移動不改變織圖 ID、名稱、檔案、作品 usage、閱讀狀態或最近開啟時間。

## 刪除資料匣

- 空資料匣與非空資料匣都要求確認。
- 非空確認文案必須明確說明織圖數量以及所有織圖會移到「未分類」。
- 確認後執行單一 store 交易，不逐筆發布畫面更新。
- 刪除完成後，如果目前正在顯示該資料匣，返回「未分類」。
- 本操作只刪資料匣，不刪除任何 `StoredPattern`、`PatternAsset`、作品 usage、閱讀資料或標記。

## 搜尋與排序

- 「全部」內的搜尋沿用現有搜尋欄位，搜尋所有織圖。
- 「未分類」或使用者資料匣內的搜尋只處理目前集合。
- 搜尋不跨集合偷偷顯示其他資料匣的結果。
- 清除搜尋後回到目前集合，不重設資料匣選取。
- 既有「最近加入」與「名稱」排序維持，套用在篩選後的集合。
- 資料匣名稱不納入織圖內容搜尋；資料匣側欄本版本不新增獨立搜尋。

## 本地化與無障礙

新增介面 key 必須完整存在於主 App 現有 13 種語言，包含：

- 全部、未分類、資料匣、建立、重新命名、刪除、移到資料匣。
- 名稱重複、名稱空白、保存失敗與刪除確認。
- 織圖數量的正確單複數／複數規則。

要求：

- 所有 App 文字依 KnitNote 目前選擇的 locale 即時顯示。
- 資料匣名稱與織圖名稱維持使用者原文。
- VoiceOver 讀出資料匣名稱、織圖數量、是否選取及按鈕用途。
- context menu 與圖示按鈕需有完整可本地化 label/hint。
- Dynamic Type 放大時，側欄列可增高或換行，不裁掉名稱或數量。

## 錯誤與競態

- 新增／改名期間若另一操作建立同名資料匣，以 store 提交時的最新快照重新驗證並拒絕重複。
- 移動時若目的資料匣已被刪除，操作失敗並保持原歸屬。
- 移動時若織圖已被刪除，不發布資料匣或選取變更。
- 刪除時若資料匣內容已變動，確認後以提交時的實際內容全部移到「未分類」，錯誤訊息不得宣稱錯誤數量。
- 還原或載入遇到孤立參照時保留織圖並降級到「未分類」，同時讓診斷／測試可觀察修復結果。

## 驗證

### 自動測試

- 毛線庫 title 必須明確綁定目前 locale-aware resolver；禁止回退為直接 key 的 `navigationTitle`。
- 在執行中切換至少三種 locale，毛線庫標題立即更新。
- archive schema、舊版解碼、正常 round trip、備份及還原保存資料匣關係。
- 舊資料升級後所有織圖、資產、usage 與閱讀資料不變，且歸入「未分類」。
- 新增、改名、重複名稱、空白名稱、移動、無變更移動、刪除空／非空資料匣。
- 保存失敗與 stale ID 不改變記憶體、generation、選取或 archive。
- 孤立 folder ID 安全歸入「未分類」。
- 「全部」與選定資料匣的搜尋範圍正確。
- iPhone 導覽結構與 iPad／Mac sidebar/detail 結構有來源或行為契約。
- 13 語言 key、token、plural 與 VoiceOver label/hint 完整。
- iOS Simulator、macOS 及相關 Share target 無簽名 build 通過；若資料模型供 Share Extension 解碼，需加入相容測試。

### 實機驗收

- iPhone：新增資料匣、進出清單、匯入、長按移動、搜尋與返回流程。
- iPad：側欄與清單左右排列，在直向、橫向及窄 split view 都可操作。
- Mac：側欄選取、滑鼠 context menu、鍵盤焦點、視窗縮放與搜尋。
- 至少在繁體中文、英文及另一非拉丁語言間切換，確認毛線庫標題及資料匣系統文字立即更新。
- VoiceOver 驗證資料匣名稱、數量、新增、移動、重新命名與刪除確認。
- 驗收前後核對既有織圖、PDF／圖片／YouTube 資產、作品連結、閱讀頁碼、標記及備份內容均未遺失。

## 回歸保護

- 不修改織圖原始檔或資產去重規則。
- 不改變一份織圖可連結多個作品的能力。
- 不改變作品專屬閱讀狀態、頁面筆記、高亮或手寫標記。
- 不改變永久刪除織圖與解除作品連結的既有語意。
- 不翻譯任何使用者輸入或匯入內容。
- 不以自動測試或成功 build 取代 iPhone、iPad、Mac 與 VoiceOver 的實機驗收。
