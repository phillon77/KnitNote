# KnitNote 智慧編織提醒 2.0 設計

日期：2026-08-28

狀態：已完成互動式設計確認，待使用者審閱書面規格

基準：`main` at `ca21951eada053fdf651ce851c7c34324e6023bc`

## 目標

將 KnitNote 1.5.1 現有的單一計數器提醒擴充成作品層級的多提醒工作流程，讓使用者能在第 1 組主計數器上同時安排單次與重複的編織指示，並在 iPhone、iPad、Mac 與 Apple Watch 上可靠處理。

本功能延續 KnitNote 安靜、清楚、不強迫中斷編織的產品方向。提醒使用畫面內卡片與輕微觸覺回饋，不新增背景推播、通知權限、帳號或開發者伺服器。

## 已確認的產品決定

- 新提醒固定跟隨每件作品的第 1 組計數器。重新命名或選取其他計數器不改變主計數器身分。
- 同一作品可同時建立多條提醒。
- 支援單次與重複提醒。
- 重複提醒可指定次數，或持續到使用者停用。
- 提醒以非阻斷式卡片與一次輕微觸覺回饋呈現。
- 第一次可選擇「稍後提醒」，並在下一排再顯示一次；第二次不再允許延後。
- 已完成的提醒不因計數器倒退及再次經過觸發排而自動重開。
- 使用者可從提醒清單手動將項目重設為未完成。
- 提供加針、減針、換色、麻花、開扣眼、量尺寸等常用類型，也允許自訂文字。
- Apple Watch 只負責顯示、完成、稍後提醒及略過，不提供新增或編輯。
- 既有六組計數器提醒與進度必須無損保留。

## 範圍

### 包含

- 作品層級提醒集合與既有提醒遷移。
- 第 1 組主計數器的多提醒建立、編輯、排序、停用、刪除及重設。
- 單次、有限重複與無限重複規則。
- 同排多項提醒與跨排直接輸入的完整評估。
- 作品頁與織圖閱讀頁的入口及提醒卡。
- Apple Watch 提醒顯示與可靠離線操作。
- 備份、還原、語言、無障礙及候選驗收。

### 不包含

- 第 2 至第 6 組計數器建立新的多提醒。
- iCloud 或其他雲端同步。
- 背景通知、推播通知、通知權限或時間型提醒。
- 依 PDF 格線或高亮位置自動推進提醒。
- 自動分析織圖、辨識針法或產生提醒。
- Apple Watch 上新增或編輯規則。

## 現有行為與變更理由

KnitNote 1.5.1 的 `ProjectCounter` 可保存一個 `CounterReminder`。現有規則支援單次或從設定當下開始的固定間隔重複，並可同步到 Apple Watch；提醒卡提供完成與停止。此結構無法讓第 1 組計數器同時安排多個不同指示，也沒有下一排再提醒、常用類型、完整清單或手動重設。

本次採用獨立的作品提醒集合，而不是把 `ProjectCounter.reminder` 直接改成陣列。提醒是作品工作流程的一部分；獨立集合可提供排序、同排佇列與日後清楚的列表操作，同時用明確的 `counterID` 保存舊提醒原本的依據。

## 資料模型

每件 `StoredProject` 新增 `knittingReminders: [KnittingReminder]`。核心型別固定使用下列名稱，避免 UI、儲存與 Watch 各自發明不同語意。

```swift
struct KnittingReminder: Identifiable, Codable, Hashable, Sendable {
    let id: UUID
    let counterID: UUID
    var kind: KnittingReminderKind
    var customText: String?
    var rule: KnittingReminderRule
    var progress: KnittingReminderProgress
    var state: KnittingReminderState
    var mutationRevision: UInt64
    let createdAt: Date
}
```

`KnittingReminderProgress` 保存已排程、已完成與已略過次數、下一個目標，以及按觸發順序排列的待處理 occurrence。每個 `KnittingReminderOccurrence` 有獨立 ID、原始目標排數、目前顯示排數，以及 `initial` 或 `deferredOnce` 階段。這讓同排多項、一次跨越多次重複與 Watch 離線指令都能精確指向單一 occurrence。已結束 occurrence 不保存無限歷史；規則只保存累計完成／略過次數及最近一次已處理 occurrence，供使用者執行一次手動重設。

### 提醒類型

`KnittingReminderKind` 包含：

- increase：加針
- decrease：減針
- changeYarn：換色
- cable：麻花
- buttonhole：開扣眼
- measure：量尺寸
- custom：自訂

常用類型是語意值，不保存目前語言的顯示字串。自訂文字由使用者輸入並原樣保存，不做翻譯。

### 規則

- 單次：指定絕對目標排數。
- 重複：指定第一個絕對目標排數、間隔，以及可選的總次數。
- 重複總次數為 `nil` 時持續到停用。

重複提醒必須保存明確的第一個目標，而不是僅以建立當下的計數值作為隱含錨點。這能讓畫面摘要、編輯與資料遷移保持可理解。

### 進度與狀態

每條提醒保存：

- 已排程次數。
- 已完成或略過次數。
- 下一個目標排數。
- 目前待處理的 occurrence 識別資訊。
- 是否為第一次顯示或已延後到下一排。
- 啟用、完成或停用狀態。
- 資料修訂值，用於 Watch 指令的樂觀更新與衝突拒絕。

「稍後提醒」只改變目前 occurrence 的處理狀態與再次顯示排數，不建立新的規則 occurrence，也不增加規則已完成次數。

## 主計數器規則

- 第 1 組計數器以穩定的 `counterID` 判定，而非陣列當下顯示名稱或 `selectedCounterID`。
- 新提醒的 `counterID` 必須是作品標準化後第 1 組計數器的 ID。
- 切換目前選取的計數器不影響提醒。
- 重新命名、計數器畫面重排或語言切換不影響提醒。
- 若解碼資料缺少其 `counterID`，該提醒視為無效資料；載入不得部分發布或自行改綁到另一組計數器。

## 觸發與狀態轉換

### 計數增加

當第 1 組計數器由舊值增加到新值時，核心一次評估所有啟用提醒：

1. 找出 `(舊值, 新值]` 內的所有目標 occurrence。
2. 按目標排數、提醒建立順序及穩定 ID 排序。
3. 為每個 occurrence 建立待處理狀態。
4. 即使直接輸入由 10 跳至 25，也不得漏掉期間的提醒。
5. 若一次跨過同一重複規則的多個 occurrence，各 occurrence 都必須可辨識；畫面可摘要數量，但完成狀態不得合併到無法追蹤。

### 計數減少或歸零

- 計數器倒退不自動重開已完成、已略過或已停用 occurrence。
- 尚未處理的 occurrence 保留，不因倒退而消失。
- 使用者如因拆織需要重新執行，可在清單中手動重設指定提醒；系統不得猜測拆織意圖。

### 完成

- 「完成」只處理目前卡片所指向的 occurrence。
- 完成後有限重複規則推進下一目標；最後一次完成後規則進入完成狀態。
- 單次規則完成後進入完成狀態。

### 稍後提醒與略過

- occurrence 第一次出現時提供「完成」及「稍後提醒」。
- 選擇「稍後提醒」後，在主計數器下一次增加一排時重新顯示。
- 再次顯示時提供「完成」及「略過這次」，不再提供第二次延後。
- 「略過這次」結束該 occurrence，並以已略過狀態保留紀錄；重複規則照常安排下一次。
- 使用者離開再回到作品時，尚未處理或已延後且符合再次顯示條件的 occurrence 不得遺失。

### 同排多項提醒

- 同一排觸發多條提醒時，顯示單一容器，標示項目總數並逐項處理。
- 不在作品頁垂直堆疊多張大型卡片。
- 處理完目前項目後顯示下一項；已處理項目不可因重繪再次出現。

### 停用、刪除與重設

- 停用規則保留歷史與進度，不再產生新 occurrence。
- 刪除規則需要確認，並移除該規則及待處理 occurrence。
- 「重設為未完成」只針對該規則最近一次完成或略過的 occurrence。確認後以同一原始目標建立新的待處理 occurrence，立即排入卡片佇列；不改變主計數器、不回退累計排程，也不複製下一個未來 occurrence。每條規則只保留最近一次已處理項目可供重設，避免無限規則累積無界歷史。
- 編輯已產生進度的規則前顯示新摘要並要求確認；提交採原子替換，不留下新舊規則混合狀態。

## 作品頁與提醒清單

### 入口

- 第 1 組主計數器旁顯示「提醒」入口及啟用數量。
- 織圖閱讀畫面提供同一提醒清單的快捷入口。
- 兩個入口使用相同資料與編輯流程，不建立織圖專屬副本。

### 清單

- 啟用提醒依下一目標排數排序。
- 清單同時顯示遷移自第 2 至第 6 組計數器的舊提醒，並清楚標示其原計數器名稱；「新增提醒」仍固定建立在第 1 組。
- 每列顯示類型、文字、下一目標及規則摘要。
- 提供編輯、停用、刪除與重設。
- 已完成與已停用項目收在可展開的「已結束」區域。
- 作品完成後整份清單唯讀；恢復作品後使用原進度繼續。

### 新增與編輯

流程依序為：

1. 選擇常用類型或自訂。
2. 輸入非必填補充文字。
3. 選擇單次或重複。
4. 設定第一個目標排數。
5. 重複規則設定間隔，並選擇指定次數或持續到停用。
6. 儲存前顯示完整摘要，例如「從第 10 排開始，每 4 排提醒加針，共 6 次」。

驗證失敗時在欄位附近說明原因，不清除其他有效輸入。

## 提醒卡與觸覺回饋

- 提醒卡使用現有水彩視覺語言，置於計數器下方，不遮住計數按鈕。
- 卡片是非阻斷式；使用者可繼續查看作品或織圖。
- 新 occurrence 首次成為可見項目時只給一次輕微觸覺回饋。
- SwiftUI 重繪、切換頁籤或再次進入畫面不應重複震動同一首次顯示。
- iPad、Mac 及無觸覺能力的環境安靜忽略回饋，不視為錯誤。
- 首次卡片動作為「完成」與「稍後提醒」。再次卡片動作為「完成」與「略過這次」。
- 「停用規則」放在更多選單或提醒詳細頁，避免誤觸。

## Apple Watch

### 顯示與操作

- Watch 顯示提醒類型、使用者文字、觸發排數及佇列位置。
- 首次顯示提供完成與稍後提醒。
- 延後後再次顯示提供完成與略過這次。
- 多項同時觸發時顯示項目數並逐項處理。
- Watch 不顯示新增或編輯控制。

### 快照與指令

Watch 快照必須能表示提醒清單及待處理 occurrence；同步 schema 需正式升版並拒絕不支援版本。每個 Watch 動作至少包含：

- 指令 ID。
- 作品、計數器、提醒及 occurrence ID。
- 預期的提醒修訂值或等價版本資訊。
- 動作種類：完成、稍後、略過。

現有可靠佇列、去重 ledger、prepare/apply/acknowledge 邊界繼續使用。不得另建一條不具持久化保證的提醒捷徑。

### 離線與衝突

- Watch 離線時將計數與提醒動作依順序寫入既有本機可靠佇列。
- iPhone 作品資料是最終依據。
- 同一指令重送只執行一次。
- 已在 iPhone 完成、刪除、重設或替換的 occurrence 收到舊 Watch 指令時，拒絕該指令並刷新快照。
- 拒絕提醒指令不得回滾成功的其他計數指令。
- 同步失敗時保留待送操作並顯示簡短狀態，不靜默丟失。

## 舊資料遷移

### 遷移來源

目前每個 `ProjectCounter` 可保存一個 `CounterReminder`。載入舊 schema 時，將所有六組計數器的現有提醒逐一轉換到作品提醒集合：

- 保留提醒 ID 或建立可追溯的穩定 ID 映射。
- 保留原 `counterID`，包括第 2 至第 6 組的既有提醒。
- 保留訊息、規則、錨點、下一目標、已確認次數、待處理 occurrence、啟用狀態及修訂值。
- 舊重複規則的第一個目標須由 `anchorValue + interval` 精確推導。

### 相容政策

- 遷移後的第 2 至第 6 組舊提醒仍依原計數器觸發、顯示及允許完成、停用或刪除。
- UI 不允許在第 2 至第 6 組新增提醒。
- 編輯舊次要計數器提醒時可修改其既有規則，但不得改綁到其他計數器或新增第二條。
- 新資料只寫作品提醒集合，不再雙寫 `ProjectCounter.reminder`。

### 原子性與失敗

- 完整解碼、驗證及轉換成功後，才發布或持久化新資料。
- 任一提醒無法安全轉換時，整份 archive 載入失敗，不做部分遷移或靜默丟棄。
- 保留既有原子寫入與最後已知良好 archive。
- 顯示可重試的資料載入錯誤；不得以空提醒清單覆蓋原資料。

## 備份與還原

- 專案 archive schema 正式升版。
- 備份包含完整提醒集合、規則、進度、待處理與延後狀態。
- 新版備份 manifest 只升級格式版本並沿用既有內容摘要；本功能不新增提醒數量等 manifest 摘要欄位。提醒只能從 archive 本體還原，不得依 manifest 摘要重建。
- 還原舊版備份走相同遷移器，不複製第二套轉換邏輯。
- 還原先完成預檢與轉換，再原子替換現有資料。
- 無效、未知版本、重複 ID、缺少計數器參照或不合理數值均拒絕還原，現有資料保持不變。

## 本地化

- 常用提醒類型、規則摘要、狀態、按鈕、錯誤與無障礙文字涵蓋 KnitNote 現有全部支援語言。
- 數字、排數、複數與句子順序使用目前選擇的 App locale。
- 使用者輸入的提醒文字原樣保存，不翻譯、不改寫。
- Apple Watch 使用 KnitNote 投影的語言選擇；語言切換後重新解析系統字串，而非保存舊語言快照。
- localization contract 必須驗證 key 集合、format 參數及各 target 資源一致。

## 無障礙與跨平台行為

- VoiceOver／macOS VoiceOver 朗讀提醒類型、文字、觸發排、佇列位置及可用動作。
- Dynamic Type 不截斷主要內容；極大字體可將按鈕改為垂直排列。
- 所有互動控制至少 44×44 點。
- Mac 支援 Tab／Shift-Tab、Return 預設動作、Escape 關閉與清楚焦點順序。
- 顏色不作為提醒類型或狀態的唯一辨識方式。
- Reduce Motion 不影響提醒出現與處理，只停用非必要動畫。

## 驗證策略

### 核心單元測試

- 單次、有限重複、無限重複的建立與驗證。
- 多提醒依主計數器一次評估。
- 同排多項、一次跨越多排及同規則多個 occurrence。
- 完成、延後、下一排再顯示、第二次略過、停用、刪除及重設。
- 計數倒退與歸零不重開已處理 occurrence。
- 整數溢位、無效間隔、無效目標、重複 ID 與缺少計數器參照。
- 編輯規則的原子替換與 stale revision 拒絕。

### 儲存與遷移測試

- 六組舊提醒完整遷移且保持原 counter ID 與進度。
- 遷移失敗不發布、不持久化、不清理原資料。
- 新 archive 往返、重新啟動與作品完成／恢復。
- 舊版及新版備份還原。
- 損壞、未知版本、部分資料與 persistence failure 的回滾。

### Watch 測試

- 新快照 schema 驗證與舊 schema 拒絕。
- 多提醒投影、排序與語言投影。
- 完成、稍後、略過的在線、離線、重送與 acknowledgement。
- stale revision、已刪除 occurrence、指令順序與重新握手。
- 計數與提醒指令各自可靠，單一拒絕不破壞其他成功動作。

### UI 與契約測試

- 作品頁入口、啟用數量、提醒清單、新增／編輯摘要。
- 織圖快捷入口使用相同資料。
- 同排單卡佇列與按鈕狀態。
- 已完成作品唯讀。
- 全語言 key、Dynamic Type、VoiceOver 與 44×44 點觸控。

### 實體驗收

- iPhone：建立、觸發、多項處理、倒退及重新啟動。
- iPad：自適應版面、織圖快捷入口與多工尺寸。
- Mac：鍵盤、焦點、編輯與資料保留。
- Apple Watch：在線、離線、重新連線、觸覺回饋及多項佇列。
- 覆蓋安裝：舊六組提醒、作品、織圖、毛線、日誌及其他資料不變。

各平台驗收結果分別記錄；模擬器、單元測試或單一裝置通過不得代替其他實體表面。

## 錯誤處理與安全不變量

- 所有 reminder mutation 需經 `JSONProjectStore` 的授權、序列化、持久化及發布邊界。
- UI 不直接修改持久模型。
- 完成、稍後、略過、停用與刪除均以提醒 ID、occurrence ID 及修訂值驗證目標。
- 失敗不得造成部分完成、重複完成或計數器回滾。
- 作品完成狀態、試用／解鎖限制與既有 Watch entitlement 規則繼續適用。
- 不新增分析、追蹤、帳號、伺服器或通知權限。
